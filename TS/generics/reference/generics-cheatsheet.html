Generic functions (Lesson 1)

PatternSyntaxNotes
Declare a type parameter function f<T>(x: T): T The function is generic because it declares T.
Arrow function const f = <T,>(x: T): T => x The trailing comma stops .tsx files reading <T> as JSX.
Inferred call f(42) → T = number Inferred from the runtime arguments. Hover the call to see it.
Explicit type argument fetchJson<User>(url) Required when T appears only in the return type. Explicit beats inferred.
Several type parameters function pair<A, B>(a: A, b: B): [A, B] Each one is inferred independently.

Parameter vs argument

function fetchJson<T>(url: string): Promise<T>   // T    = type PARAMETER (declaration)
fetchJson<User>("/api/me")                      // User = type ARGUMENT  (use site)

Rules of thumb

  • If the input type should flow to the output, use a generic, not any or unknown.
  • Ask: where is T declared, where does the input use it, where does the output use it?
  • A type argument is trusted, not checked at runtime. fetchJson<User> is a promise the caller makes.
